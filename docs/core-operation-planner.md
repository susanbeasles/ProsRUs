# Core operation planner and lifecycle

This product-owned capability is the sole pure derivation for the existing 14 domain mutations. It imports the actual shared catalog and established domain rules; it does not authorize callers, allocate IDs, inspect providers, read storage or select current time. Existing generic saves remain inert.

## API and source identity

- `parseDomainOperation(value)` validates a closed registered operation/input pair using the shared catalog. No additional public tool or caller field exists.
- `selectCoreReads(operation, allocation, observed?)` derives finite record IDs, complete collection labels and canonical source keys. The first call selects direct dependencies; repeated calls can add only verified selected-row dependencies. `validateCoreObservation` rejects incomplete or surplus records, bindings, collections, source keys and immutable packet evidence.
- `planCoreOperation(input)` receives validated operation/input, stable host allocation, detached observations and current host-owned evidence. It returns a `domain-plan-v1` with all candidates, exact guards, effects, durable audits and result mapping. `phase: baseline-archive-v1` is a private prerequisite branch of this same planner.
- `runCoreOperation(request, ports)` orchestrates the retained root, separate prerequisite baseline and public mutation through existing host-owned effects. The actual Control registry, current authority and Coordinator adapters belong to Task4I.

`planner.sourceDigest` is generated from maintained planner/lifecycle entries and their transitive relative source graph, the actual shared module, dependency lock and generator itself. `integration/core-planner-source.json` lists every path/hash. The generated identity module and manifest are excluded from their own graph. `npm run check:core-planner` verifies exact generated bytes. Host and Product must use identical reviewed graph/sidecar bytes; a fixture constant or caller override is not valid provenance.

## Stable input and current evidence

Host allocation pins workspace, actor, request root, business time, candidate entity/lineage and audit identities before derivation. `coreInputDigest` uses the existing shared invocation-input canonical meaning; `domainRequestDigest` uses explicit domain-request-v1 meaning. Attempt transaction/version IDs and workspace chain retries are outside that stable meaning.

Every selected present record, including source-only dependencies, has exact raw JSON/revision/time plus a current committed binding with the same revision and exactly one selected head. Mutation planning requires a nonnull version; only exact selected baseline prerequisites allow null/empty bindings, and already committed baseline dependencies remain fully checked. Creation roles deliberately require allocated-target absence; collisions never turn claim/thread/offer/new-opportunity/packet/attempt creation into an update. Packet, submission and interview claim eligibility requires exact current claim version/revision and independently resolved current review/permission identity/revision/expiry. `source_supported` also needs existing actual original descriptors and separately current source-use permission. Stored status/permitted fields, historical approval, upload purpose strings and shaped JSON do not create authority. Task4I resolves and revalidates live permission at preparation, durable boundary and acknowledgment. Current-proof fixtures in Task4D tests are synthetic effect seams only.

A new upload-backed artifact/evidence/resume can support claim evidence through optional `readSet.archiveSources` while having no legacy artifact record. Each guard binds exact immutable source entity/kind/lineage/version/manifest, the canonical signed snapshot projection bytes, full original artifact0 descriptor, single current head and explicit legacy artifact absence. Package and sink validate the selected manifest/closure; migration0004 atomically checks current projection/head, finite-kind identity uniqueness across both lineages and projections, and continued legacy absence. An incomplete alias is a conflict. Atomic archive-source guard failures use the established typed DomainError with exact RECOVERY_DOMAIN_ARCHIVE_SOURCE_CONFLICT code and status409; rollback tests assert class/code/status as well as unchanged tables. Generic JSON is never activated or converted into a legacy row.

The retained historical capture tuple is finite profile-source correspondence data: original SOURCE SAVE request root, its committed transaction, upload handle and purpose digest. Task4I independently resolves append-only begin/request/session/handle binding and the existing signed `accepted-upload-origin-v1` prepared audit event, verifies full committed original bytes and separately resolves current permission. No new manifest field or independent issuer exists. Old absent fields retain historical hash bytes.

## Baseline and retry behavior

An unversioned selected legacy row first receives a separately committed inert baseline through the same prepared/package/sign/store path. The baseline preserves observed raw-body bytes, exact revision/time and migration provenance separately, and emits zero business mutations, source-key changes or operational audit. Safe incomplete legacy claims remain quarantined; unsafe/malformed interpretation is blocked.

For a legacy binary original, Task4I's finite resolver binds exact old locator, row revision and raw-body digest. Observed bytes come from an existing full committed source or the same bounded internal byte intake under the original registered invocation/root; generated row/snapshot JSON cannot be the original. Missing remains honest partial history and cannot qualify source-supported evidence. Permission/capture unavailable is a blocker, not absence. No fake public upload invocation or new purpose/grant is introduced.

The host retains the original business observation and exact baseline/main plans using existing root CAS. Every retained nonnull binding must equal its fresh counterpart before baseline effects. The internal bindCommittedBaseline effect returns {observation,candidateVersions} assembled by Task4I from the exact genuinely committed retained preparation/D1 winner; a primary SaveVersionResult alone does not identify companion versions, and mapping-shaped data is not commitment proof. The lifecycle validates the existing strict role/version mapping, primary save.versionId and exact kind/entity/lineage/revision/source mapping for every former-null row. Null-to-version fresh changes require that exact retained committed prerequisite; unknown or uncommitted changes conflict without effects. A complete current reread after binding must equal the verified bound observation before main derivation. Committed result lookup occurs before mutable derivation on replay and verifies actual D1 plus retained exact preparation/candidate/result mapping. A successful baseline followed by failed main save leaves the public mutation unsaved; retry reuses the baseline and retained main meaning. Lost responses reconcile the actual winner. Changed input, source evidence or guarded business reads conflict. A workspace-chain retry obtains a new accepted attempt under the same stable plan/digest. Queue wake failure does not undo a committed result because the existing durable outbox owns retry.

## Operation outputs

Claim add/review, profile conflict resolve, opportunity capture/assess/transition, conversation capture/draft, interview prep and settings save have their finite selected primary candidate. Packet create atomically includes packet and opportunity; submission record includes attempt and opportunity with opportunity as public result; offer record includes offer and opportunity; first conversation association includes thread and association question. Existing capture/prep/association preserves the exact current business body/revision without new operational audit. No same-transaction candidate can masquerade as committed evidence.

## Verification and limits

`npm run test:core` exercises real production planner/package/signer/R2/D1 primitives with bounded original bytes and race rollback controls. Full unit tests include old absent-field golden contracts. No live grants, providers, deployment, custody assertion or production Control/Coordinator assembly is established by these fixtures. Actual Task4I wiring and independent review of the final source graph remain required.
