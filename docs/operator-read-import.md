# Local operator-only read import

This adapter is locally qualified against synthetic inputs. It is not a production activation certificate. Product owns this importer and its kernel. The separate Control host owns registration and its existing signed-owner proof. There is no app/public import route, queue, cron, new credential, or generic SQL capability.

## Parent and child contract

The trusted parent first verifies the accepted source closure and retains exact approval outside source/history/assets. Its private `OperatorApproval` binds one action, fixed window, mode, account, created database, bucket, manifest-specific keys, original byte sizes/hashes, profile/plan identities and source closure. Resource names are never defaults. The exact declared key map is retained without renaming: at most five distinct keys, each at most 1024 UTF-8 bytes, under the exact slash-terminated namespace. Nonempty ASCII letter/digit/underscore/hyphen/dot segments are accepted; dot-only traversal segments, empty segments, URI authorities, percent escapes and cross-namespace keys reject before effects. `namespaceExclusive: true` means the parent has established one coordinated exact-input writer; the adapter provides no conditional PUT, storage lock or independent custody.

Use `prepareOperatorInput` on those trusted inputs in the parent. It rebuilds the plan, takes exact SQL and parameters from the owning kernel, freezes the result and measures all complete escaped frame/code/tool/batch envelopes before any original upload. A same-labelled modified statement, bind, target or reordered effect is rejected before dispatch.

The credential-free child is `node scripts/run-operator.mjs ABSOLUTE_PLAN ABSOLUTE_PROFILE ABSOLUTE_APPROVAL`, from the reviewed Product root with the existing pinned dependencies available. Each private file must be exact canonical JSON.stringify bytes (no BOM, duplicates, extra whitespace or silent normalization); the plan/profile digests bind these exact bytes. Supply only the three private files and a minimal environment (for example PATH and CLOUDFLARE_CF_FETCH_ENABLED=false). Never pass credentials or copy private files into the repository. The runner does not read credentials, invoke tools or listen on a socket. Its local build cache contains source only. Do not assume this subprocess is an OS security sandbox.

The parent supplies `createParentBroker(prepared, {current, dispatch})` and routes each newline-terminated canonical child frame into `broker.accept`. Return the resulting canonical response plus one newline to the child's stdin. Close stdin after the successful `done` response, await actual child exit, then call `broker.finish`. The local synthetic subprocess test demonstrates this exact finite interface.

`current` must check the real parent task's current approval, stop state and immutable deadline, each time called. It must not be a historical boolean or child decision. `dispatch(args, effect)` is an external parent port: invoke exactly one actual `cloudflare_execute(args)` per admitted management effect, decode only the closed normalized result, and retain the real pending invocation until settlement. No tool or credential acquisition is implemented in this package. The source-owned `connectorEnvelope` contains the fixed request template; never execute JavaScript supplied by the child. Parent tool availability and permissions remain external gates, not a feature fabricated by the subprocess.

Call `broker.stop()` on stop/expiry. An outstanding connector call may be uncancellable; a stopped caller must retain ownership until that call settles. A timeout does not establish rollback. Keep the bounded parent state receipt, especially `batchOutcome`, and report unknown or committed-but-unacknowledged honestly. Do not start another write, retry automatically, renew the action or reuse a historical approval. Reconciliation requires a new, separately retained, currently authorized `mode: reconcile` action. Its broker cannot dispatch PUT or batch writes.

## Admission and semantics

Hard reject ceilings: five sources, 154 roles, 512 KiB per original and 2.5 MiB combined, 5000 UTF-8 profile bytes, 8 MiB plan and four chunks; logical request 4 MiB and response 2 MiB; read/write fragments 48 KiB, 256 nonempty and 32 empty fragments, 30-second no-progress timeout clipped to the original deadline. One effect is outstanding. The 16 MiB unfinished frame/request/result/source-relay budget is logical accounting, not a physical-memory guarantee. Complete code, tool arguments and atomic SQL batch are limited to 6, 8 and 4 MiB respectively. All escaping/base64/wrappers count.

Business limits are 34 management requests (R2 25, D1 9), 24 SQL statements and 128 protocol frames including current/done frames. Neither batch nor action can be split to fit. The dormant qualification constants allow at most eight separately approved synthetic management calls (D1 five/eight SQL, R2 three, one <=1024-byte fixture). They do not implement, authorize or automatically run live probes.

Originals are verified byte-for-byte from R2 before insert-only D1 work. Different preexisting bytes conflict. Both first and last throwing clock guards sample the same immutable bounds in the one atomic batch; the last follows every insert. The final boundary is final SQL time, not physical acknowledgement time. No staged action record is added. The published LOCAL seed wrapper is unchanged.

Imported records remain `legacy_unversioned` with `legacy_imported_archive_pending` receipt and pending original baselines. No canonical version, pursuit, intent, approval, outreach or independent-protection completion is created. Existing read-only consumers and uncertainty labels are unchanged.

## Unqualified activation gates

Exact current source publication/signing and proper Control repository base; actual signed provider hardware/MFA claims and fresh owner browser behavior; exact resource/account/import permission; and actual connector binary representation, fully prepared envelope acceptance, D1 REST atomicity/order/error semantics and current/primary readback remain open. The generated D1 query body is `{batch: statements}` for single reads and the atomic write; SQL, order and numeric clock/timestamp parameters are preserved exactly. The documented REST schema describes string parameters, so actual numeric parameter acceptance/type preservation remains an explicit compatibility gate; never silently stringify clock parameters. The candidate connector template accepts a closed raw-base64 representation or a bounded scalar UTF-8 string normalized to base64, but neither branch is live-qualified merely by its presence. Metadata, ETags or parsed/re-serialized JSON are insufficient. Local Workerd bindings do not qualify these REST/connector behaviors. Failed or ambiguous primitives stop dependent work; no automatic runtime substitution is provided.

`npm run test:operator` runs the focused broker/subprocess and Workerd checks and is part of normal `npm run verify`. `npm run typecheck:operator` checks the actual strict kernel/operator/shared-read consumers. Tests use only synthetic inputs. Existing cached dependencies are not clean-install evidence.

## Narrow UTF-8 response adapter candidate

The fixed connector envelope can normalize a complete string result to the existing base64 broker shape. It rejects unpaired UTF-16 surrogates and pre/post-encoding bounds, preserves BOM, Unicode, whitespace, newlines and JSON escape bytes without parsing, and avoids whole-buffer argument spreading. The trusted broker still requires canonical base64 and exact original size/SHA256; this is hash-based integrity, not an extra literal-byte comparison. A connector that already repaired invalid raw UTF-8 is detected only by comparison to the admitted original size/hash. This is not arbitrary-binary support.

Live Uint8Array/application-json PUT, complete GET representation, maximum envelopes and missing-key behavior remain unqualified. Generic provider exceptions propagate; no message-text mapping to absence is allowed. The existing returned structured404 branch is unchanged and not evidence that the real connector returns it. No original upload is authorized by local adapter tests.
