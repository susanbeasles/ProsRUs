# Local operator-only read import

This adapter is locally qualified against synthetic inputs. It is not a production activation certificate. Product owns this importer and its kernel. The separate Control host owns registration and its existing signed-owner proof. There is no app/public import route, queue, cron, new credential, or generic SQL capability.

## Parent and child contract

The trusted parent first verifies the accepted source closure and retains exact approval outside source/history/assets. Its private `OperatorApproval` binds one action, fixed window, mode, account, created database, bucket, manifest-specific keys, original byte sizes/hashes, profile/plan identities and source closure. Resource names are never defaults. The exact declared key map is retained without renaming: at most five distinct keys, each at most 1024 UTF-8 bytes, under the exact slash-terminated namespace. Nonempty ASCII letter/digit/underscore/hyphen/dot segments are accepted; dot-only traversal segments, empty segments, URI authorities, percent escapes and cross-namespace keys reject before effects. `namespaceExclusive: true` means the parent has established one coordinated exact-input writer; the adapter provides no conditional PUT, storage lock or independent custody.

Use `prepareOperatorInput` on those trusted inputs in the parent. It rebuilds the plan, takes exact SQL and parameters from the owning kernel, freezes the result and measures all complete escaped frame/code/tool/batch envelopes before any original upload. A same-labelled modified statement, bind, target or reordered effect is rejected before dispatch.

The credential-free child is `node scripts/run-operator.mjs ABSOLUTE_PLAN ABSOLUTE_PROFILE ABSOLUTE_APPROVAL`, from the reviewed Product root with the existing pinned dependencies available. Each private file must be exact canonical JSON.stringify bytes (no BOM, duplicates, extra whitespace or silent normalization); the plan/profile digests bind these exact bytes. Supply only the three private files and a minimal environment (for example PATH and CLOUDFLARE_CF_FETCH_ENABLED=false). Never pass credentials or copy private files into the repository. The runner does not read credentials, invoke tools or listen on a socket. Its local build cache contains source only. Do not assume this subprocess is an OS security sandbox.

The parent supplies `createParentBroker(prepared, {current, dispatch})` and routes each newline-terminated canonical child frame into `broker.accept`. Return the resulting canonical response plus one newline to the child's stdin. Close stdin after the successful `done` response, await actual child exit, then call `broker.finish`. The local synthetic subprocess test demonstrates this exact finite interface.

`current` must check the real parent task's current approval, stop state and immutable deadline, each time called. It must not be a historical boolean or child decision. `dispatch(args, effect)` is an external parent port: invoke exactly one actual `cloudflare_execute(args)` per admitted management effect, decode only the closed normalized result, and retain the real pending invocation until settlement. No tool or credential acquisition is implemented in this package. The source-owned `connectorEnvelope` contains the fixed request template; never execute JavaScript supplied by the child. Parent tool availability and permissions remain external gates, not a feature fabricated by the subprocess.

Call `broker.stop()` on stop/expiry. An outstanding connector call may be uncancellable; a stopped caller must retain ownership until that call settles. A timeout does not establish rollback. Keep the bounded parent state receipt, especially `batchOutcome`, and report unknown or committed-but-unacknowledged honestly. Do not start another write, retry automatically, renew the action or reuse a historical approval. Reconciliation requires a new, separately retained, currently authorized `mode: reconcile` action. Its broker cannot dispatch PUT or batch writes.

## Admission and semantics

Hard reject ceilings: five sources, 154 roles, 512 KiB per original and 2.5 MiB combined, 5000 UTF-8 profile bytes, 8 MiB plan and four chunks; logical request 4 MiB and response 2 MiB; read/write fragments 48 KiB, 256 nonempty and 32 empty fragments, 30-second no-progress timeout clipped to the original deadline. One effect is outstanding. The 16 MiB unfinished frame/request/result/source-relay budget is logical accounting, not a physical-memory guarantee. Complete code, tool arguments and atomic SQL batch are limited to 6, 8 and 4 MiB respectively. All escaping/base64/wrappers count.

Business limits are 34 logical management dispatches (R2 25, D1 9), 24 SQL statements and 128 protocol frames including current/done frames. Neither batch nor action can be split to fit. The dormant qualification constants allow at most eight separately approved synthetic management calls (D1 five/eight SQL, R2 three, one <=1024-byte fixture). They do not implement, authorize or automatically run live probes.

Originals are verified byte-for-byte from R2 before insert-only D1 work. Different preexisting bytes conflict. Both first and last throwing clock guards sample the same immutable bounds in the one atomic batch; the last follows every insert. The final boundary is final SQL time, not physical acknowledgement time. No staged action record is added. The published LOCAL seed wrapper is unchanged.

Imported records remain `legacy_unversioned` with `legacy_imported_archive_pending` receipt and pending original baselines. No canonical version, pursuit, intent, approval, outreach or independent-protection completion is created. Existing read-only consumers and uncertainty labels are unchanged.

## Unqualified activation gates

Exact current source publication/signing and proper Control repository base; actual signed provider hardware/MFA claims and fresh owner browser behavior; exact resource/account/import permission; and actual emitted complete-read template qualification, fully prepared envelope acceptance, D1 REST atomicity/order/error semantics and current/primary readback remain open. The generated D1 query body is `{batch: statements}` for single reads and the atomic write; SQL, order and numeric clock/timestamp parameters are preserved exactly. The documented REST schema describes string parameters, so actual numeric parameter acceptance/type preservation remains an explicit compatibility gate; never silently stringify clock parameters. The operator GET now uses the fixed raw-response template described below. The earlier scalar/base64 conversion is superseded for operator GET; its historical local qualification does not prove this template deployed. Local Workerd bindings do not qualify the deployed proxy, REST retry behavior or provider cancellation. Failed or ambiguous primitives stop dependent work; no automatic runtime substitution is provided.

`npm run test:operator` runs the focused broker/subprocess and Workerd checks and is part of normal `npm run verify`. `npm run typecheck:operator` checks the actual strict kernel/operator/shared-read consumers. Tests use only synthetic inputs. Existing cached dependencies are not clean-install evidence.

## Complete remote-read receipt boundary

The source-owned GET template uses `fetch` on the fixed `https://api.cloudflare.com/client/v4/accounts/.../r2/buckets/.../objects/...` resource, GET and manual redirects. It supplies no credentials or caller headers. The trusted outer proxy owns existing authentication. `connectorEnvelope` now requires the admitted source and exact request frame for GET; D1/PUT templates are unchanged. Prepared source bytes are checked against approval again before they enter the emitted code. No provider or child value supplies expected bytes.

For HTTP200 the actual response body is streamed to EOF, without text/JSON decoding, under the admitted positive size (at most 512 KiB), 1024 total chunks, 32 empty chunks and a 30-second deadline clipped to approval expiry. Declared Content-Length is checked against observed bytes; nonidentity encoding, redirects, partial responses, short/extra/empty reads, stream errors and ambiguous statuses fail. An independent deadline race covers fetch, every stream read and SHA256 computation; abort is requested and a potentially hanging reader cancellation is never awaited. Cleanup/physical proxy settlement is not proven by local cancellation.

Only after EOF does the emitted code hash observed bytes with SHA256 and literally compare them with the exact admitted original. It returns a closed `job-stack.remote-original-read.v1` receipt, at most 2048 UTF-8 bytes. Account, bucket, key, source name, action digest, sequence and request digest bind the exact invocation; size/hash are computed from the remote body. Complete code, tool arguments and the worst-case receipt are measured before effects, within all existing limits. No base64 or original content is returned through tool output.

Only actual HTTP404 plus a complete <=8192-byte strict JSON envelope (`success:false`, `result:null`, empty messages and nonempty errors each containing only numeric code 10007 and nonempty message) emits the separate bound `job-stack.remote-original-absent.v1` receipt. Parent accepts it only for initial custody-get. Null, text error messages, malformed/overbound envelopes, duplicate JSON keys and another invocation's receipt cannot authorize PUT. Final/original/reconciliation absence always fails.

Parent and child independently validate the closed receipt against the dispatched frame and admitted source. The kernel's separately named source-only `observeOperatorPendingCompleteReads` entry accepts an explicit `OperatorCompleteReadPorts.originalReads` function capability. It validates resource/action/source identity, complete receipt shape and exact GET request digest, with increasing request sequence. This trusted function port is supplied only by the source-owned operator adapter after parent exchange validation. It is not a public DTO option or cryptographic attestation of an arbitrary dispatcher. A hostile or substituted trusted dispatcher remains outside this boundary's guarantee. The existing `observeAuditedPending` and `observeOperatorPending` raw-copy entries still require and hash actual `Uint8Array` values; adding an evidence-shaped DTO does not select evidence mode. No local prepared bytes are substituted as remote raw copies.

Current authority, stop/expiry, one in-flight dispatch and pre/post-await checks remain mandatory, including after final proof and before acknowledgement. A final failure can leave an earlier batch committed but unacknowledged; it never becomes success. Tests cover actual emitted bytes at 95, 273231 and 524288 bytes, hostile streams, strict absence, replay/forgery, unchanged raw-copy behavior and local D1/R2 parent/child/kernel integration. Raw-binary template fixtures do not relax audited source admission.

## Physical retries remain an activation blocker

Pinned public proxy source at `cloudflare/mcp` commit `d5d326e5d4dd09af4af1f2ea9926df2a991582c2` retries network failures and HTTP429 up to 3 times for every method. Thus 34 logical dispatches can mean up to 136 physical attempts: R2<=100 and D1<=36. The deployed proxy identity is not established by that source inspection. No undocumented retry-disable flag is used.

Repeated GET is harmless read-only verification. Repeated PUT uses the same immutable key and approved literal bytes under the existing exclusive-namespace assumption, making content idempotent; versions, metadata and request counts need not be identical. Preexisting conflicting bytes still deny. R2 has no server clock/authority guard equivalent to D1, so a hidden delayed retry may write after local expiry. This receipt correction does not fix that mutation issue, extend authority or make private import ready.

D1 remains one insert-only batch with initial and final SQL clock guards and unique-conflict behavior. A repeated committed write should conflict/roll back; a transport failure remains unknown until separately authorized reconciliation. A retry after expiry must fail the server-side clock guard and roll back. These local SQL properties do not certify deployed REST atomicity, numeric parameter semantics, per-attempt authority or cancellation. Preserve `effect-outcome-unknown`, `batchOutcome:unknown` or committed-but-unacknowledged as observed. A separate mutation-transport design/qualification is required before private import activation.
