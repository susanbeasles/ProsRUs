# Implemented shared gateway contract

Control owns the existing canonical issuer `https://control.vespoli.me` and canonical `/mcp` audience. Job Stack uses closed selected-v2 workspace grants with exact current owner/data owner, capability revision, workspace selectors and operation authority. Infrastructure or broad profile sessions do not imply Job Stack authority. Reads enabled in the Product: `job_stack_records`, `job_stack_pipeline_page`, `job_stack_version`, `job_stack_versions`, `job_stack_request` and `job_stack_protection` (`job_stack_session` is answered by Control). Owner commands are routed by the finite registry in `src/application/commands/registry.ts` ([ADR 0001](adr/0001-finite-command-registry.md)): local-writes `claim.add`, `claim.review`*, `profile.conflict.resolve`*, `opportunity.capture/assess/transition`, `conversation.capture/associate`, `conversation.draft.save`, `interview.prepare`, `offer.record`, `settings.update`* and `version.save`; intake `upload.begin/chunk/complete`. Unavailable with a recorded reason: `packet.create`, `submission.record`, `meeting.import`, `profile.export`; external effects (send, scheduling, mail sync, discovery, document import, queue, cron) stay gated. This guide adds no scope, grant kind or route.

Authority per effect: every read and command takes fresh `read` decisions and exactly one `before-ack` from `CONTROL_AUTHORITY.revalidate`; nothing is asked after `before-ack` and a denial is terminal. Write effects (`local-write`, `intake`) additionally require Control's scope and hardware elevation before an invocation is minted. Owner-only operations (*) also require `entrypoint: 'owner'` with `verifiedOwnerPrincipalId` equal to the grant issuer. Local-writes take `before-ack` immediately before the single recovery commit batch and need Control preparation signing (`signPreparation`) verified against `RECOVERY_TRUST_ROOT`; the current Control implements only `revalidate`, so versioned saves deny until it signs. Error codes returned to Control are fixed lowercase kebab-case values (`operation-denied`, `operation-unavailable`, `request-key-conflict`, domain codes such as `revision-conflict`).

The Control `JOB_STACK` binding selects the private Product service `job-stack-staging`, named entrypoint `JobStack`. The Product default fetch answers only `GET /.well-known/release-marker` and returns 404 for every other path. The packaged Product's reciprocal `CONTROL_AUTHORITY` binding selects Control's named `JobStackAuthority` entrypoint. Product/Coordinator read and before-ack guards revalidate current authority; supplied profile data or historical imported observations never establish grants, versions, protection or pursuit approval.

Owner presentation requires genuine signed Access identity through the shared checked private contact gate. Job Stack additionally requires an explicitly configured, independently qualified hardware-assurance profile and bounded lease. Existing sessions bind selected grant/revisions, stable proof context and target; deadlines only narrow, expiry/revocation is terminal, and reads/refresh cannot establish or extend a lease. Selected owner operations use same-origin one-use nonces bound to the exact presentation, grant, method and target. The optional exact owner presentation origin serves approved owner GET presentation/data paths and explicit same-origin, one-use-nonce-bound session establish/revoke POSTs. Productive alias POSTs remain unavailable; OAuth/MCP/protocol metadata remain canonical. Product asset requests receive sanitized URL/GET requests without credential or assertion forwarding.
